# Аудит анимаций на телефоне — 20 сентября 2026

Проверена опубликованная версия `77b01e6a9f952258eea5f7b7f4ca1508af6dd7b1`: https://newsch8l.github.io/mistakery/?story=live-agent . Код приложения не менялся.

## Главный вывод

Оба описанных симптома воспроизводятся при `prefers-reduced-motion: reduce`: точки печати получают почти нулевую длительность бесконечного цикла, а эффекты исходов явно отключены. Это подтверждено в Chromium и WebKit с мобильными профилями. Настройка на телефоне пользователя пока неизвестна, поэтому совпадение с его конкретным случаем требует подтверждения.

## Подтверждённые находки

### 1. Высокий приоритет: уменьшение движения ускоряет бесконечную анимацию печати

`style.css:422` задаёт `typingBlink 1.1s infinite`. Глобальное правило в `style.css:766` меняет длительность на `.01ms`, сохраняя бесконечные повторы и задержки точек 180/360 мс. Цикл становится в 110 000 раз короче. Это скорость CSS timeline, не количество реально отображаемых кадров: на экране возможны мерцание, неравномерность или почти неподвижные точки из-за выборки по кадрам.

Воспроизведение: мобильный профиль, reduced motion, карта LIVE_AGENT_04B → левый ответ → LIVE_AGENT_05. Через примерно секунду первая точка находится на итерации 99 165 в Chromium / 100 599 в WebKit. В обычном режиме цикл 1,1 с, около одной итерации за секунду.

Исправление: явный спокойный вариант индикатора при reduced motion, предпочтительно статические точки/надпись. Убрать почти нулевой бесконечный цикл. Системную настройку доступности не обходить.

### 2. Отключение анимаций исходов в reduced motion — текущая политика

`style.css:767–771` задаёт `animation: none` для сцены, свечения, пульса и изображения. Все 20 исходов в обоих движках имеют отключённые эффекты при reduced motion. На реальном переходе LIVE_AGENT_01 → правый ответ → исход 0 нет событий запуска анимации и изменения transform.

Без reduced motion у всех 20 исходов назначены ожидаемые анимации. На реальном переходе исхода 0 подтверждены изменяющийся transform и события завершения jolt (360 мс) / pulse (620 мс). Цвет и надпись SUCCESS/FAILURE сохраняются в обоих режимах; Padel сохраняет ранее согласованную локацию вместо баннера.

Это объясняет исчезновение движения при данной настройке, но само уважение настройки не является дефектом. Нужен отчётливый статический сигнал исхода для этого режима; движение/мигание нельзя просто принудительно включить всем.

### 3. Средний приоритет: эффект изображения проходит до его загрузки

`app.js:739–753` запускает эффекты сразу при рендере и сразу отмечает исход показанным. Готовность изображения не учитывается. В `style.css:703` эффект `outcomeSignal` длится 420 мс.

При искусственной задержке запроса `live-agent-judgment-day.webp` на 2,2 с изображение стало готово через 1 586 мс после рендера в Chromium и 2 120 мс в WebKit (запрос preload начинается раньше рендера). Эффект закончился через 435/422 мс. На загруженном фото эффект уже не виден. Это подтверждено при выключенном reduced motion; причина независима от системной настройки.

Исправление: синхронизировать эффект самого изображения с успешной загрузкой/декодированием, с ограниченным ожиданием и проверкой актуальности карты. Текст и итог ресурсов должны оставаться доступными; навигация/Back не должны запускать устаревший эффект.

### 4. Средний приоритет: повторное касание обрывает показ исхода

`app.js:191` разблокирует следующий ответ через 280 мс. Успех длится 700 мс, свечение — 900 мс. При касании через ~310 мс после перехода LIVE_AGENT_08 → левый ответ → успешный исход приложение уже принимает следующий выбор и уходит в Investor. Зафиксированы `animationcancel` всех трёх эффектов на ~325 мс Chromium / 303 мс WebKit.

Исправление: отдельное короткое окно защиты от случайного повторного касания при входе в исход, согласованное с фазой показа. Не блокировать игру бесконечно при отключённых анимациях или отсутствующем animationend.

## Темп и заметность — дополнительные наблюдения

- Двухсекундная пауза сообщений не ускоряется: в четырёх профилях окончание замечено через 2 010–2 011 мс (опрос каждые 250 мс, это не точный замер задержки таймера). На момент начала измерения оставалось 1 989–1 997 мс.
- После паузы сообщения добавляются пакетом с разницей старта 90 мс (`app.js:817–819`), а не имитируют отдельное набирание каждого текста. Это может выглядеть быстро и без системной настройки; изменение такого ритма — отдельное решение о темпе диалога.
- Движение поражения — только ±2 CSS px за 360 мс, успеха — масштаб .985→1.012→1. На небольшом экране эффекты короткие; факт их запуска не гарантирует субъективную заметность.
- Back намеренно не повторяет анимацию исхода. Это существующее требование, не новая поломка.

## Как проверялось

| Движок / профиль | Режим | Цикл точек | Реальный переход в исход |
|---|---|---|---|
| Chromium / Pixel 7, touch | обычный | 1,1 с | jolt и pulse запустились/завершились |
| Chromium / Pixel 7, touch | reduced motion | 0,01 мс, infinite | эффекты отсутствуют |
| WebKit / iPhone 13, touch | обычный | 1,1 с | jolt и pulse запустились/завершились |
| WebKit / iPhone 13, touch | reduced motion | 0,01 мс, infinite | эффекты отсутствуют |

- Публичный сайт: HTTP 200, ошибок JavaScript нет в четырёх основных проходах.
- Для каждой комбинации проверены CSS-состояния 20 исходов; для перехода в исход 0 — реальные касания, покадровые значения transform/opacity и события анимаций.
- Проверены скриншоты WebKit обычного/reduced режима. Статические снимки использованы для оценки представления, а движение подтверждено временными измерениями.
- Для медленной картинки применена контролируемая задержка только одного запроса.
- Повторное касание выполнено через `touchscreen.tap` по координатам. Обычный `locator.tap` ждёт стабильности движущейся кнопки и скрывает этот случай: первая такая проба дождалась завершения эффектов, затем метод был скорректирован.
- Существующие проверки: `node --test --test-concurrency=3 tests/outcome-presentation.browser.test.cjs tests/innovation-typing.browser.test.cjs tests/legal-typing.browser.test.cjs tests/continuation-focus.browser.test.cjs` — 5/5 passed.
- Пробел покрытия: тесты подтверждают CSS-имена, намеренное отсутствие эффектов при reduced motion и паузы сообщений; они не ловят бесконечный сверхкороткий цикл точек, готовность картинки и быстрый raw touch.
- Сводные измерения: `2026-09-20-mobile-motion-evidence.json` рядом с отчётом.

Ограничение: это запуски браузерных движков на компьютере с мобильными viewport/DPR/user-agent/touch, не физические iPhone/Android. Модель телефона, браузер, системный reduced motion и энергосбережение пользователя пока не подтверждены. FPS, тепловое ограничение, реальную мобильную частоту обновления и поведение встроенного браузера этот аудит не устанавливает.
